# Examples

This document provides runnable examples for common usage patterns.

## Prerequisites

1. Operator deployed to `operators` namespace
2. Garage instance accessible at admin endpoint
3. Admin token available as Kubernetes Secret

## Step 1: Create admin token Secret

Create Secret in `operators` namespace (required for operator to access Garage):

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: garage-admin-secret
  namespace: operators
type: Opaque
stringData:
  token: "your-garage-admin-token-here"
```

```bash
kubectl create secret generic garage-admin-secret \
  --from-literal=token=YOUR_TOKEN \
  -n operators
```

## Step 2: Create GarageStore (or GarageClusterStore)

**Option A: Namespace-scoped GarageStore** (recommended for multi-tenant)

```yaml
apiVersion: smokingcat.net/v1alpha1
kind: GarageStore
metadata:
  name: production
  namespace: storage
spec:
  adminURL: http://admin.garage.smokingcat.net:3903
  adminToken:
    name: garage-admin-secret
    # Note: token Secret must exist in operators namespace
```

**Option B: Cluster-scoped GarageClusterStore** (shared, single admin token)

```yaml
apiVersion: smokingcat.net/v1alpha1
kind: GarageClusterStore
metadata:
  name: production
spec:
  adminURL: http://admin.garage.smokingcat.net:3903
  adminToken:
    name: garage-admin-secret
    # Note: token Secret must exist in operators namespace
```

Apply and verify Ready:

```bash
kubectl apply -f garagestore.yaml
kubectl get garagestore -n storage
kubectl describe garagestore production -n storage
```

## Step 3: Create GarageBucket

```yaml
apiVersion: smokingcat.net/v1alpha1
kind: GarageBucket
metadata:
  name: app-data
  namespace: storage
spec:
  clusterRef:
    name: production  # Points to GarageStore in same namespace
  globalAlias: app-data-bucket
  quotas:
    maxSize: 1099511627776  # 1 TB
```

Verify:

```bash
kubectl get garagebucket -n storage
kubectl describe garagebucket app-data -n storage
```

## Step 4: Create GarageKey

Operator automatically creates a Kubernetes Secret with credentials:

```yaml
apiVersion: smokingcat.net/v1alpha1
kind: GarageKey
metadata:
  name: app-writer
  namespace: storage
spec:
  bucketRef:
    name: app-data
  bucketPermissions:
    read: true
    write: true
    owner: false
```

Verify:

```bash
kubectl get garagekey -n storage
kubectl get secret app-writer-credentials -n storage -o yaml
```

Credentials Secret contains:

- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `AWS_S3_ENDPOINT`
- `AWS_REGION`
- `bucket_name`

Use in Deployment:

```yaml
spec:
  containers:
  - name: app
    env:
    - name: AWS_ACCESS_KEY_ID
      valueFrom:
        secretKeyRef:
          name: app-writer-credentials
          key: AWS_ACCESS_KEY_ID
    - name: AWS_SECRET_ACCESS_KEY
      valueFrom:
        secretKeyRef:
          name: app-writer-credentials
          key: AWS_SECRET_ACCESS_KEY
```

## Security Model

**Admin credentials (Store):**

- Stored in Secret in `operators` namespace
- Only operator can read (least privilege RBAC)
- No Deployment or pod can access it

**Application credentials (Key):**

- Generated by operator from Garage
- Stored in Secret in same namespace as GarageKey
- Applications can reference Secret from same namespace

This enforces isolation: apps cannot access admin token, operator cannot be compromised by app permissions.
